# OMIYAcappella — Website

大宮アカペラプラットフォーム **OMIYAcappella**（[@OMIYAacappella](https://x.com/OMIYAacappella)）の
Webサイトです。

> **公開中: <https://omiyacappella.com>**（2026-08-25 公開）
> Cloudflare Workers で配信。`main` に push すると自動でデプロイされます。
> 日本語がルート、英語が `/en/` 以下。合計12ページ。

**既知の不具合がひとつあります。連絡フォームからメールが届きません。**
詳細は [05 Contact](#05-contact) を参照してください。

### ページの編集方法

ルート直下の `*.html` は **`scripts/assemble.py` が生成したもの**です。直接編集しても
次に生成した時点で消えます。

- **中身を直す** → `parts/*.html`（hero / about / gallery / projects / x / contact / rules / footer）
- **その英訳を直す** → `parts/en/*.html`（ファイル名は日本語版と同じ）
- **ヘッダー・フッター・ナビ・トップの構成を直す** → `scripts/assemble.py`
- **タイトル・説明文・パンくず・MENUカードの文言** → `scripts/assemble.py` の `JA` / `EN`

編集したら生成します。

```bash
python3 scripts/assemble.py
```

日本語がデフォルトでルート直下、英語は `en/` に出力されます。ヘッダーの JA / EN
スイッチと `hreflang` は自動で相互にリンクされます。`parts/en/` に対応するファイルが
無いとビルドは止まります（英訳の入れ忘れをそのまま公開しないためです）。

公開URLは `scripts/assemble.py` の `SITE_URL` 1か所から組み立てています。デプロイ先が
変わったら、必ずここを直してから生成してください。

## ローカルで見る

```bash
python3 scripts/dev-server.py 4321
```

その後ブラウザで <http://localhost:4321> を開きます。
（`file://` で直接開くと相対パスが解決されないため、サーバ経由が必要です）

`python3 -m http.server` ではなく専用サーバを使っているのは、**CSSやJSを編集しても
ブラウザが古いファイルを掴んだままになる**のを防ぐためです。すべて `no-store` で返します。

### スマホで見る

同じWi-Fiにつないだうえで、Macのローカルアドレスを開きます。

```bash
ipconfig getifaddr en0        # 例) 192.168.0.85
```

スマホのブラウザで `http://<表示されたアドレス>:4321` を開けば、そのまま実機で確認できます。
Macがスリープするか、サーバを止めると見られなくなります。
外出先の相手にも見せたい場合は、公開（デプロイ）が必要です。

## デザイン方針

- ロゴ・Xバナーの配色（黄 / サーモン / ティール / グリーンの4円 ＋「大宮」のオレンジ）を
  そのままデザイントークンに落とし込み、サイト全体の色をブランドと一致させています。
- 参考にいただいた採用サイトに倣い、**セクション番号（01〜05）＋大きな見出し＋広い余白**の
  縦積みレイアウト、背景に薄いゴースト数字、区切りの幾何学モチーフ（ひし形）を採用。
- 背景はクリーム（`--paper`）とその一段濃い色（`--paper-2`）の2色を交互に使い、
  全カテゴリを同じトーンで統一しています（濃色のセクションはフッターのみ）。
- Aboutの4つの小カテゴリは `.subsec` という共通コンポーネントで、
  オレンジの縦罫＋通し番号（01 — 1 …）＋見出し＋リード文の形をそろえています。
  冒頭の導入文と写真は小カテゴリの外側に置き、セクション全体の入口にしています
  （小カテゴリと同じ見出しが二度出るのを避けるため）。
- スクロール連動のフェードイン、ヘッダーの追従、ナビのスクロール・スパイを実装。
- `prefers-reduced-motion` に対応（アニメーションを無効化）。
- ブレークポイントは 1024px / 980px / 620px。980px 以下でハンバーガーメニューに切り替わります。

- 「すべて／演奏動画／音源」で絞り込み。カードをクリックすると
  **ページを離れずにライトボックスで再生**します（← → で移動、Esc で閉じる）。

- 動画はブラウザ標準の `<video>`、音源は `<audio>` で再生します。
  全画面はブラウザ標準の全画面ボタンから利用できます。
- **全14件**（演奏動画8／音源6）。すべて @OMIYAacappella の投稿が出典です。
  件数はページ上には出していません（数えられると少なく見えるため）。
- 文字だけの画像は掲載せず、**人が写っているものだけ**を載せる方針です。
- **音源の投稿はサムネイルを使いません。** 元の動画がボイスメモの画面録画、または
  ロゴのタイトル画像なので、そのまま出すと見栄えが悪くなります。
  代わりに `assets/img/wave.svg`（ブランド4色の波形）を敷いた専用カードを描画しています。
- 追加するときは `parts/gallery.html`（英語版は `parts/en/gallery.html`）の
  `.gal-grid` に1ブロック足して `python3 scripts/assemble.py` を実行します。
  演奏動画は `gal-item--video` + サムネイル画像、音源は `gal-item--audio` + `gal-item__wave` です。
- 写真も表示できます（ライトボックスの拡大表示は実装済みのまま残してあります）。
  `data-kind="photo"` と `data-src` / `data-caption` / `data-href` を持つ `<button>` を追加し、
  絞り込みに `<button data-filter="photo">写真</button>` を戻してください。
- 音源ファイル（mp3など）を直接置く場合は `assets/audio/` を作り、
  カードに `<audio controls>` を差し込む構成を想定しています。

#### 動画・音源をサイトで配信している理由

当初はXの投稿を埋め込んで再生する構成でしたが、次の2点で断念しました。

1. **`video.twimg.com` がリファラによるホットリンクを拒否します。**
   Referer なしなら 200、他サイトからの Referer 付きだと 403 が返ります。
   そのため `<video src="https://video.twimg.com/...">` は再生できません。
2. **Xの埋め込みウィジェットが安定しません。** 応答しない時間帯があり、
   その間はモーダルが読み込み中のまま止まります。

そこで、Xに投稿されている14本を `assets/video/` に置いて自前で配信しています。
いずれも OMIYAcappella 自身が撮影・公開したものです。
再生に失敗した場合は、Xの投稿ページへのリンクを表示するようにしてあります。

> 容量は計89MB（最大でも1ファイル15.6MB）です。GitHub Pages / Netlify の無料枠で問題ありませんが、
> 軽くしたい場合は 640×360 の変換版に差し替えれば1/3程度になります。

  | 項目 | クラス／要素 | 備考 |

  | 種別 | `.tag--kind` / `.tag--note` | 企画募集・イベント・交流・ノート |

### 04 X

- **Xの埋め込みは一切使っていません。** プロフィールのタイムライン埋め込みは廃止済み
  （`tfw_legacy_timeline_sunset: true`／iframeが高さ0）、個別投稿の埋め込みも応答しない
  時間帯があり、そのあいだセクションが真っ白になるためです。
  本文・画像・動画のすべてをこのサイトから配信する**自前のカード**として描画しています。
- **引用（quote）は表示しません。** 引用先が同じ一覧の別カードであることが多く、
  同じ内容が画面に2回出てしまうためです。

#### 毎日の自動更新（GitHub Actions・無料）

`.github/workflows/x-latest.yml` が **毎日6:00（JST）** に
`scripts/fetch-x-latest.mjs` を実行し、変化があったときだけコミットします。

```
Playwright で x.com/OMIYAacappella を開く
  → 固定ポスト以外の投稿IDを収集（記事の先頭が「固定」かどうかで判別）
  → 各IDを X の syndication エンドポイントに問い合わせ（APIキー不要）
  → 投稿日でソートして新しい3件
  → 画像・動画・サムネイルを assets/data/x-media/ に保存（古い分は削除）
  → assets/data/x-latest.json を書き出し
```

| 項目 | |
| --- | --- |
| 費用 | **¥0**（Actionsの無料枠。1回1〜2分、月30〜60分） |
| 実行 | 毎日1回＋Actionsタブの「Run workflow」から手動実行も可 |
| 動画 | 25MBを超えるものは保存せず、サムネイル＋Xへのリンクに切り替わります |
| 失敗時 | 何も書き換えません。前回のJSONがそのまま残ります |
| JSONもない場合 | `main.js` の `LATEST_POSTS`（3件を直書き）にフォールバック |

**つまり、取得に失敗してもセクションが空になることはありません。**

X側の仕様変更で止まる可能性はあります。その場合は Actions のログにエラーが出て、
サイトは最後に取得できた3件を表示し続けます。

### 05 Contact <a id="05-contact"></a>

- ページ上にメールアドレスは出していません。送信は `/api/contact`（`worker/index.js`）を
  経由し、宛先は Cloudflare のシークレットに置いています。
- **問い合わせ種別で「参加を希望する」を選んだときだけ、7項目が追加で現れます。**
  性別・年齢・居住地（都道府県）・所属サークル名・アカペラ歴・可能パート（Lead / 1st /
  2nd / 3rd / 4th / Bass / Percussion の複数選択）が必須、SNSアカウント名が任意です。
  他の種別に切り替えると非表示に戻り、**入力値もチェックもクリアされます**
  （無関係な個人情報を送らないため）。
- 宛先はふたつあります。

  | | 設定場所 | 用途 |
  | --- | --- | --- |
  | 主 | シークレット `CONTACT_ENDPOINT` | サークル管理者のアドレス |
  | 副 | `worker/index.js` の `CONTACT_CC_DEFAULT` | もう一名の運営へ Cc |

  副をコードに置いてあるのは、シークレット任せにするとダッシュボードでの設定を
  忘れたときに黙って Cc が消えるためです。`CONTACT_CC` シークレットで上書きでき、
  空文字を設定すると Cc を止められます。このリポジトリを public にする場合は、
  アドレスをシークレットへ移してください。
- スパム対策として honeypot（`_honey`）を仕込んであります。埋まっていれば 200 を返し、
  実際には送信しません（ボットに気づかせないため）。

#### ⚠️ 未解決: FormSubmit が Cloudflare からの送信を拒否します

現在の転送先 [FormSubmit](https://formsubmit.co/) は、**Cloudflare Workers の IP からの
リクエストに常に HTTP 429 を返します。** 同じ時刻に同じ宛先へ家庭用回線から POST すると
200 が返るため、送信元 IP で拒否されていると考えられます。**そのため、これまで
問い合わせメールは一通も配信されていません。**

切り分けの過程で、あわせて2つの不具合を修正しました。

1. **`Origin` ヘッダーが無かった。** FormSubmit はこれが無いと「ファイルから開いた
   ページ」とみなし、送信せずに案内文を返します。ブラウザなら自動で付きますが、
   サーバ側から転送する Worker は自分で付ける必要がありました。
2. **拒否も HTTP 200 で返ってくる。** 本文の `success:"false"` を見ていなかったため、
   **実際には送られていないのに「送信しました」と表示していました。** 現在は
   FormSubmit の理由をそのまま 502 で返します。

残る選択肢は、フォームのアクティベート（管理者宛の "Activate Form" リンク）を済ませて
再試験するか、**Resend への移行**です。Resend は Workers からの利用を公式に想定しており、
月3,000通まで無料、`omiyacappella.com` は既に Cloudflare 上にあるので DNS 設定も容易です。
独自ドメインの差出人になるぶん、迷惑メール判定もされにくくなります。

## 公開（Cloudflare Workers）

**公開先: <https://omiyacappella.com>**（Cloudflare Registrar で取得・年 $10 前後）

Worker 名は `omiyacappella-site`。ダッシュボードの Workers Builds が
`DKon109/omiyacappella-site`（private）に接続されていて、`main` に push するたびに
自動でビルド・デプロイされます。

| 設定項目 | 値 |
| --- | --- |
| Build command | `bash scripts/build.sh` |
| Deploy command | `npx wrangler deploy` |
| Production branch | `main` |

`wrangler.toml` が `dist/` を静的アセットとして配信し、`/api/contact` だけ Worker が受けます。
独自ドメインは `wrangler.toml` の `routes` で apex のみに紐づけています。

**このビルドコマンドは必須です。** 出力をリポジトリのルートにすると、
`README.md`・`server/`・`scripts/` がそのままURLで閲覧できてしまいます。
`scripts/build.sh` は各ページ（`en/` を含む）・`assets/`・`robots.txt` / `sitemap.xml` と
`_headers` だけを `dist/` に集めます。

### ⚠️ シークレットを変えたら「デプロイ」まで必要です

この Worker はバージョン方式で動いています。**ダッシュボードでシークレットを追加しても、
新しいバージョンが作られるだけで有効になりません。** Deployments タブでそのバージョンを
Promote するまで、稼働中のコードからは見えないままです。

`npx wrangler secret put` も、最新バージョンが未デプロイだとエラーで止まります。その場合は

```bash
npx wrangler versions deploy      # 対話でバージョンを選び 100% にする
```

またはダッシュボードの Version History から Promote してください。

### URL は拡張子なしです

Cloudflare の静的アセット配信は既定で `.html` を落とし、付いたままの URL を 307 で
リダイレクトします。そのため canonical・hreflang・sitemap・内部リンクのすべてを
**拡張子なしの形**（`/about`、`/en/about`）で出力しています。`scripts/dev-server.py` も
同じ対応をするので、ローカルと本番でリンクの意味が食い違いません。

生成される URL は `scripts/assemble.py` の `SITE_URL` 1か所から組み立てています。
**デプロイ先を変えたら、必ずここを直してから生成してください。** canonical が存在しない
ホストを指すと、Google に「このサイトはインデックスしなくてよい」と伝えることになります。

### ドメインの集約

同じ内容が複数の URL で見えると検索評価が分散するため、入口を apex ひとつに寄せています。

| 経路 | 状態 |
| --- | --- |
| `www.omiyacappella.com` | DNS に CNAME（Proxied）＋ Redirect Rule で 301 → apex |
| `http://` | SSL/TLS → Always Use HTTPS で 301 → https |
| `omiyacappella-site.ryoji3348.workers.dev` | Worker の Domains タブで**無効化済み** |


`CONTACT_ENDPOINT` を試したいときは `.dev.vars` に書きます（gitignore済み）。

無料枠との関係:

### アクセス解析

**Cloudflare Web Analytics が稼働中です。設定作業はありません。** ドメインが Cloudflare 上に
あるため、ブラウザからの HTML リクエストに対してエッジで自動的に計測タグが挿入されます
（`curl` などでは挿入されないので、ソースを見ても出てきません）。

Cookie も localStorage も使わないため、**同意バナーは不要**です。Google Analytics に
変えるとバナーが必要になります。

`scripts/assemble.py` に `ANALYTICS_TOKEN` を用意してありますが、**空のままにしてください。**
埋めると自動挿入と二重に計測されます。Cloudflare 以外へ移転したときのための備えです。
