# OMIYAcappella — Website Prototype

大宮アカペラプラットフォーム **OMIYAcappella**（[@OMIYAacappella](https://x.com/OMIYAacappella)）の
Webサイト・プロトタイプです。運営メンバーへの提示用で、まだ本番公開はしていません。

> **Status: プロトタイプ**
> 画面右下に `PROTOTYPE` バッジを表示しています。本番公開時は `.proto-flag` を削除してください。

## 構成

```
.
├── index.html          # トップ（ヒーロー／MENU／Xでの発信／参加CTA／マーキー）
├── about.html          # OMIYAcappellaとは？（6つの決まりごと／流れ／募集要項／活動ルール）
├── gallery.html        # ギャラリー（演奏動画8・音源6）
├── projects.html       # 企画一覧（38件＋過去の企画トグル）
├── contact.html        # お問い合わせ
├── rules.html          # 活動ルール全文
├── parts/              # 各ページの中身（ここを編集する）
├── server/             # LINE Webhook → 企画一覧フィード（Cloudflare Worker）
│   └── README.md       # 料金・セットアップ手順・投稿フォーマット
├── scripts/
│   ├── assemble.py         # parts/ ＋ 共通の外枠 → 各HTMLを生成
│   ├── fetch-x-latest.mjs  # Xの最新3件を取得（GitHub Actionsから毎日実行）
│   ├── dev-server.py       # ローカルプレビュー用（キャッシュ無効）
│   ├── build.sh            # 公開用に dist/ を組み立てる
│   └── _headers            # 公開時のキャッシュ・セキュリティヘッダ
└── assets/
    ├── css/style.css   # 全スタイル（デザイントークン → セクション順）
    ├── js/main.js      # ローダー・ナビ・ギャラリー・フォーム（依存なし）
    ├── img/            # 画像一式
    ├── video/          # 演奏動画・音源（14ファイル・計89MB）
    └── data/           # Xの最新3件（GitHub Actionsが毎日更新）
```

素の HTML / CSS / JavaScript のみ。ブラウザ側の依存はありません。

### ページの編集方法

ルート直下の `*.html` は **`scripts/assemble.py` が生成したもの**です。直接編集しても
次に生成した時点で消えます。

- **中身を直す** → `parts/*.html`（hero / about / gallery / projects / x / contact / footer）
- **ヘッダー・フッター・ナビ・トップの構成を直す** → `scripts/assemble.py`

編集したら生成します。

```bash
python3 scripts/assemble.py
```

`rules.html` だけは parts を使わず単独で管理しています。

## ローカルで見る

```bash
python3 scripts/dev-server.py 4321
```

その後ブラウザで <http://localhost:4321> を開きます。
（`file://` で直接開くと相対パスが解決されないため、サーバ経由が必要です）

`python3 -m http.server` ではなく専用サーバを使っているのは、**CSSやJSを編集しても
ブラウザが古いファイルを掴んだままになる**のを防ぐためです。すべて `no-store` で返します。

### スマホで見る

同じWi-Fiにつないだうえで、Macのローカルアドレスを開きます。

```bash
ipconfig getifaddr en0        # 例) 192.168.0.85
```

スマホのブラウザで `http://<表示されたアドレス>:4321` を開けば、そのまま実機で確認できます。
Macがスリープするか、サーバを止めると見られなくなります。
外出先の相手にも見せたい場合は、公開（デプロイ）が必要です。

## デザイン方針

- ロゴ・Xバナーの配色（黄 / サーモン / ティール / グリーンの4円 ＋「大宮」のオレンジ）を
  そのままデザイントークンに落とし込み、サイト全体の色をブランドと一致させています。
- 参考にいただいた採用サイトに倣い、**セクション番号（01〜05）＋大きな見出し＋広い余白**の
  縦積みレイアウト、背景に薄いゴースト数字、区切りの幾何学モチーフ（ひし形）を採用。
- 背景はクリーム（`--paper`）とその一段濃い色（`--paper-2`）の2色を交互に使い、
  全カテゴリを同じトーンで統一しています（濃色のセクションはフッターのみ）。
- Aboutの4つの小カテゴリは `.subsec` という共通コンポーネントで、
  オレンジの縦罫＋通し番号（01 — 1 …）＋見出し＋リード文の形をそろえています。
  冒頭の導入文と写真は小カテゴリの外側に置き、セクション全体の入口にしています
  （小カテゴリと同じ見出しが二度出るのを避けるため）。
- スクロール連動のフェードイン、ヘッダーの追従、ナビのスクロール・スパイを実装。
- `prefers-reduced-motion` に対応（アニメーションを無効化）。
- ブレークポイントは 1024px / 980px / 620px。980px 以下でハンバーガーメニューに切り替わります。

## セクション別のメモ

### 02 Gallery

- 「すべて／演奏動画／音源」で絞り込み。カードをクリックすると
  **ページを離れずにライトボックスで再生**します（← → で移動、Esc で閉じる）。
  絞り込み中は、← → もその絞り込みの中だけを移動します。
- 動画はブラウザ標準の `<video>`、音源は `<audio>` で再生します。
  全画面はブラウザ標準の全画面ボタンから利用できます。
- **全14件**（演奏動画8／音源6）。すべて @OMIYAacappella の投稿が出典です。
- 文字だけの画像は掲載せず、**人が写っているものだけ**を載せる方針です。
- **音源の投稿はサムネイルを使いません。** 元の動画がボイスメモの画面録画、または
  ロゴのタイトル画像なので、そのまま出すと見栄えが悪くなります。
  代わりに `assets/img/wave.svg`（ブランド4色の波形）を敷いた専用カードを描画しています。
- 追加するときは `index.html` の `.gal-grid` に1ブロック足すだけです。
  演奏動画は `gal-item--video` + サムネイル画像、音源は `gal-item--audio` + `gal-item__wave` です。
- 写真も表示できます（ライトボックスの拡大表示は実装済みのまま残してあります）。
  `data-kind="photo"` と `data-src` / `data-caption` / `data-href` を持つ `<button>` を追加し、
  絞り込みに `<button data-filter="photo">写真</button>` を戻してください。
- 音源ファイル（mp3など）を直接置く場合は `assets/audio/` を作り、
  カードに `<audio controls>` を差し込む構成を想定しています。

#### 動画・音源をサイトで配信している理由

当初はXの投稿を埋め込んで再生する構成でしたが、次の2点で断念しました。

1. **`video.twimg.com` がリファラによるホットリンクを拒否します。**
   Referer なしなら 200、他サイトからの Referer 付きだと 403 が返ります。
   そのため `<video src="https://video.twimg.com/...">` は再生できません。
2. **Xの埋め込みウィジェットが安定しません。** 応答しない時間帯があり、
   その間はモーダルが読み込み中のまま止まります。

そこで、Xに投稿されている14本を `assets/video/` に置いて自前で配信しています。
いずれも OMIYAcappella 自身が撮影・公開したものです。
再生に失敗した場合は、Xの投稿ページへのリンクを表示するようにしてあります。

> 容量は計89MB（最大でも1ファイル15.6MB）です。GitHub Pages / Netlify の無料枠で問題ありませんが、
> 軽くしたい場合は 640×360 の変換版に差し替えれば1/3程度になります。

### 03 Projects（企画一覧）

- **LINEグループのノート（2022年4月〜2026年8月）から起こした実データ**です。全38件。
  出典の断り書きはページ上には出していません（この README が根拠の置き場です）。
- 直近3件を常時表示し、「過去の企画を見る（35件）」ボタンで残りを開閉します。件数はJS側で自動計算。
- **日付が1件だけ推定です。** 舞浜アカペラストリートに向けた企画（`2026.03`）は、
  ノートのスクリーンショットに投稿日が写っていなかったため、前後の投稿（2026.02.21 と 2026.07.05）と
  本文の「3月〜4月の土日で練習」から推定しています。正確な日付が分かれば差し替えてください。
- **投稿者名・楽譜のURL／ファイル名は一切載せていません。** 誰が何を投稿したかが分かる記述、
  飲み会の予約内容、入退会の記録もすべて除いています。掲載しているのは
  企画募集・イベント出演・運営からのお知らせだけです。
- トーク履歴の書き出しには**ノートの本文が含まれません**（`新しいノートを作成しました。` という
  行が残るだけです）。本文はノートのスクリーンショットから起こしています。
- 実データへの差し替えは `index.html` の `<article class="line-post">` を増減するだけです。
  1件あたり以下を持ちます。

  | 項目 | クラス／要素 | 備考 |
  | --- | --- | --- |
  | 日付 | `.line-post__date` | |
  | 種別 | `.tag--kind` / `.tag--note` | 企画募集・イベント・交流・ノート |
  | 状態 | `.tag--open` / `.tag--filled` / `.tag--done` | 募集中・成立・終了 |
  | 曲名／アーティスト | `.line-post__song` | |
  | 本文 | `.line-post__body` | 改行はそのまま反映されます |
  | 募集パート・練習場所など | `.line-post__foot` | 投稿者は載せません |

- **投稿者名と楽譜URLは伏せる仕様**です。`<span class="masked">非公開</span>`
  `<span class="masked">グループ内で共有</span>` を使ってください（斜線ハッチで表示されます）。
  実データを流し込む際も、この2項目は必ずマスクしたままにしてください。

#### LINEからの自動反映

`server/` に Cloudflare Worker を用意しています。詳細は
[server/README.md](server/README.md) を参照してください。

- グループで `#募集` などのマーカー付きで投稿すると、サイトに自動で追加されます。
- **月額 ¥0**（LINEのフリープラン＋Cloudflareの無料枠。Botは受信のみで、
  返信は送信通数にカウントされません）。
- **ノート・投票・アルバムはWebhookイベントが存在せず取得できません。**
  企画の詳細はノートに書かれているため、「ノートを作ったら同じ内容を
  トークにも投稿する」という運用とセットになります。
- 投稿者名・userIdは保存せず、マーカーのない投稿は読み捨てます。
- `assets/js/main.js` の `PROJECTS_ENDPOINT` が空のあいだは、
  `index.html` に書かれた既存の一覧が表示されます（Workerが落ちても壊れません）。

### 04 X

- **Xの埋め込みは一切使っていません。** プロフィールのタイムライン埋め込みは廃止済み
  （`tfw_legacy_timeline_sunset: true`／iframeが高さ0）、個別投稿の埋め込みも応答しない
  時間帯があり、そのあいだセクションが真っ白になるためです。
  本文・画像・動画のすべてをこのサイトから配信する**自前のカード**として描画しています。
- **引用（quote）は表示しません。** 引用先が同じ一覧の別カードであることが多く、
  同じ内容が画面に2回出てしまうためです。

#### 毎日の自動更新（GitHub Actions・無料）

`.github/workflows/x-latest.yml` が **毎日6:00（JST）** に
`scripts/fetch-x-latest.mjs` を実行し、変化があったときだけコミットします。

```
Playwright で x.com/OMIYAacappella を開く
  → 固定ポスト以外の投稿IDを収集（記事の先頭が「固定」かどうかで判別）
  → 各IDを X の syndication エンドポイントに問い合わせ（APIキー不要）
  → 投稿日でソートして新しい3件
  → 画像・動画・サムネイルを assets/data/x-media/ に保存（古い分は削除）
  → assets/data/x-latest.json を書き出し
```

| 項目 | |
| --- | --- |
| 費用 | **¥0**（Actionsの無料枠。1回1〜2分、月30〜60分） |
| 実行 | 毎日1回＋Actionsタブの「Run workflow」から手動実行も可 |
| 動画 | 25MBを超えるものは保存せず、サムネイル＋Xへのリンクに切り替わります |
| 失敗時 | 何も書き換えません。前回のJSONがそのまま残ります |
| JSONもない場合 | `main.js` の `LATEST_POSTS`（3件を直書き）にフォールバック |

**つまり、取得に失敗してもセクションが空になることはありません。**

X側の仕様変更で止まる可能性はあります。その場合は Actions のログにエラーが出て、
サイトは最後に取得できた3件を表示し続けます。

### 05 Contact

- ページ上にメールアドレスは表示していません。送信先は
  `assets/js/main.js` 冒頭の `FORM_ENDPOINT` で管理しています。
- 現在は [FormSubmit](https://formsubmit.co/) 経由で `REDACTED@example.com` に届く設定です。
  **最初の1回だけ、そのアドレス宛に FormSubmit から確認メールが届きます。**
  本文のリンクをクリックして有効化するまで、以降のメールは配信されません。
- 有効化すると `https://formsubmit.co/ajax/el/xxxxxxx` という別名エンドポイントが発行されます。
  これを `FORM_ENDPOINT` に差し替えると、**ソースコードからもアドレスが消えます**（推奨）。
- Formspree / Google Apps Script / サーバーレス関数など、POSTを受け付ける他のサービスでも
  そのまま動きます。`FORM_ENDPOINT = ''` にすると送信せず確認メッセージのみ返すモードになります。
- **アカペラ歴は「参加を希望する」を選んだときだけ表示され、その場合は必須**です。
  他の種別に切り替えると非表示に戻り、入力値もクリアされます。
- スパム対策として honeypot（`_honey`）を仕込んであります。

## 公開（Cloudflare Pages）

**無料・無期限**で公開できます。ビルドは不要ですが、`dist/` を組み立てる1行だけ設定します。

| Pages の設定項目 | 値 |
| --- | --- |
| ビルドコマンド | `bash scripts/build.sh` |
| ビルド出力ディレクトリ | `dist` |
| フレームワークプリセット | なし（None） |

**このビルドコマンドは必須です。** 出力ディレクトリをリポジトリのルートにすると、
`README.md`・`server/`・`scripts/` がそのままURLで閲覧できてしまいます
（この README や Worker の設定手順が公開されます）。
`scripts/build.sh` は `index.html` / `rules.html` / `assets/` と `_headers` だけを `dist/` に集めます。

無料枠との関係:

| 制限 | 現状 |
| --- | --- |
| 1ファイル 25 MiB | 最大は `keseraSera.mp4` の15.6MB。**余裕あり** |
| 1サイト 20,000ファイル | 52ファイル。**余裕あり** |
| 帯域 | 無制限 |
| ビルド回数 | 月500回。実際は更新時のみ（月数回） |

- **リポジトリがprivateのままでも公開できます**（GitHub App連携）。
- 公開範囲を運営だけに絞りたい場合は、Cloudflare Access（Zero Trust）で
  メールアドレス指定の認証を前に置けます。無料枠で50ユーザーまで。

### 公開前に決めること

1. **`FORM_ENDPOINT` のメールアドレス** — `assets/js/main.js` に平文で入っているため、
   公開すると**JavaScriptのソースから閲覧できます**。
   - 運営レビューだけなら `FORM_ENDPOINT = ''` にするのが安全（送信はされず、確認メッセージのみ）
   - 実際に動かすなら、FormSubmitを有効化して別名エンドポイント（`/ajax/el/xxxxx`）に差し替える
2. **`PROTOTYPE` バッジ** — レビュー中は付けたままを推奨。
3. **OGP画像の絶対URL化** — 公開URLが決まってから `og:image` を差し替え。
4. **`server/wrangler.toml` の `ALLOWED_ORIGIN`** — 公開URLに合わせる（LINE連携を使う場合）。
